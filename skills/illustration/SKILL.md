# 技术插图

把技术说明变成容易看懂、可以继续编辑的图。使用 Excalidraw 的白底手绘风，通过节点、分组和箭头说明关系；图中的事实来自当前项目或用户提供的材料。

## 先明确要说明什么

- 读取待配图的正文、相关源码及项目约定，确认读者需要理解的角色、职责、流程和边界。已有图稿时，优先修改原始 `.excalidraw`，保留仍然有效的内容。
- 每张图围绕一个问题组织，例如“谁与谁协作”“请求经过哪些组件”“失败后从哪里恢复”。不要为了让图更短而省略关键角色、必要的数据或失败分支。
- 按实际部署和运行方式划分边界：进程、服务、数据库、存储和外部工具是否独立，以项目事实为准。计划中的能力要明确标注，不画成已经实现的流程。
- 品牌资源、业务名称和输出路径遵循目标项目约定。通用样式在本 Skill 中维护，不将某个项目的 Logo、角色或目录规则推广到其他项目。

## 风格与布局

- 白色背景、手绘线条、简洁文字和少量浅色描边。允许线条自然起伏；不使用立体卡通、厚重阴影、渐变面板或装饰性图标底板。
- 标题直接说明主题，不固定添加项目名前缀。相邻正文已经说明主题时，图内可以省略标题。
- 主线按自然阅读方向排列，辅助关系放在相邻分支。先保证关系清楚和留白充足，再调整紧凑度。
- 同层节点使用一致的宽高。数值固定为：标题字号 28，正文字号 16，描边宽度 2，节点内边距 16，同层间距 40。箭头用实线，描边宽度 2，末端为箭头（`endArrowhead` 为 `arrow`）。不同层级的节点可以有不同宽高，字号和描边不另定一套。
- 中文以清晰易读为先，英文使用 Excalidraw 的手写字体。根据文字实际尺寸调整框和换行，不通过压缩字号塞入长段说明。
- 节点保留名称、关键职责和必要的数据；连线使用简短动词，箭头指向实际接收方。留出独立连线通道，避免交叉或穿过文字。实线与虚线只有在含义明确时才区分使用。
- 图标直接放在节点内，不额外包圆形、方形底板或光晕；保留品牌自身必要的图形和比例，不拉伸 Logo。优先复用项目已有且来源可核对的标识，配明确名称；没有合适图标时使用文字或可编辑的通用线条图形。
- 使用具体产品作为 Agent 或工具示例时，名称与角色分开说明，避免把示例画成系统唯一支持或内置的产品。
- 背景解释、类比、结论、风险说明和操作细节放在相邻正文，不在图底部堆叠大块说明条。复杂主题必要时拆成互相引用的图。

## 制作与交付

1. 先确定节点、分组和连线含义，再写成 Excalidraw JSON。源文件至少包含 `type`（值为 `excalidraw`）、`version`（值为 `2`）、`elements`，背景为白色（`appState.viewBackgroundColor` 为 `#ffffff`）。
2. 保留文字、线条与分组的可编辑性。Logo 可嵌入图稿，相关元素随节点成组移动；不要将整张图压成一张不可编辑的背景图片。
3. 本技能不写死导出命令。没有可用的导出命令时，只交付 `.excalidraw` 源文件，并在回复里写「未导出」。不把手写 SVG 或位图当作已经完成的 Excalidraw 导出。
4. 源文件路径遵循目标项目约定。插入文档时，提供准确的替代文字和源文件入口；不另存一份提示词作为事实来源。

## 看实际成图再验收

没有图形界面时，解析 `.excalidraw` JSON 做这些检查，做不到的检查不要写成已完成：

- 核对节点文字与要说明的角色、职责一致，箭头的 `startBinding` / `endBinding` 指向实际的两端节点。
- 确认没有把整张图收成一张背景图：图由可编辑的节点、连线和文字组成，而不是一张铺满画布的图片。
- 确认 `type`、`version`、`elements` 都在，背景为 `#ffffff`。

有浏览器或导出图时，再看溢出和裁切：文字完整、连线不穿过标签、嵌入文档后桌面和窄屏都没有横向溢出。没有导出图时不要写这些已经看过。过密时先减少单图信息或拆图。

交付时给出来源文件位置；实际导出了展示图时一并给出。未导出就写「未导出」。说明实际完成的检查，无法核实的内容如实标明。
